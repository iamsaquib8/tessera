# Tessera Overhaul — Design

**Status:** draft for review · **Date:** 2026-10-21 · **Owner:** Saquib

> **Your agent says done. Tessera checks.**
> Deterministic edit-safety for AI coding agents: what a change touches before
> the edit, what it broke after — across files, repos, routes, topics, and
> tables. Measured, not claimed.

---

## 1. Intent and why

Tessera should become an open-source tool that developers install because their
AI coding agent gets measurably better at something it cannot do today. Success
is real adoption, visible as GitHub stars, and a product Saquib can pitch to end
users with a live demo.

### Where Tessera is today (2026-10-20)

- 2 stars, 0 forks, last push 2026-06-22.
- Only GitHub release is v0.1.0. npm package `tessera-codegraph` was never
  published (404). crates.io is at 0.8.0 (160 downloads). CHANGELOG marks
  v0.5–v0.9 as "Unreleased" while README advertises v0.9 and install paths that
  do not work.
- ~10.5k lines of Rust, 31 CLI subcommands, 21 MCP tools, 11 languages.
- The architecture audit found the "compiler-grade precision" claim is not true
  in practice:
  - References resolve by **name only** (`to_symbol_name = ? OR LIKE '%.name'`,
    `src/query.rs:1878`), so `repo.save()` and `map.save()` collide.
  - JS/TS `new Foo()` is never recorded; there are no `extends` / `implements` /
    decorator / annotation edges; calls inside anonymous callbacks (Express
    `app.get(...)`, Jest `it(() => ...)`) have no edge.
  - Java overloads share one qualified name and attach to an arbitrary row.
  - Unsorted directory walk makes tie-breaks machine-dependent, contradicting
    the "deterministic" claim.
  - `src/indexer.rs:1138` slices `&first_line[..180]` by byte offset and
    panics on non-ASCII text, aborting the whole index.
  - MCP hard-codes protocol `2024-11-05`, returns `-32000` for every error,
    answers notifications, and has no output size cap.
  - `_meta` token and fidelity numbers are hard-coded constants, not
    measurements.
  - Dead weight: `engine.rs`, the `cozo` feature, `--graph-engine`, unused
    `petgraph`, a snapshot the MCP server never reads, and a bloom filter whose
    hash is not stable across Rust versions.

### What the market looks like (verified 2026-10-20)

"Local tree-sitter code graph over MCP" is a crowded category, not a gap:

| Project | Stars | License | Notes |
| --- | --- | --- | --- |
| graphify | ~130k | Apache-2.0 | LLM + tree-sitter graph, `/graphify` skill, YC |
| colbymchenry/codegraph | ~74.5k | MIT | SQLite/FTS5 graph, watcher, token benchmark — closest to Tessera today |
| GitNexus | ~48k | non-commercial | Browser UI, change detection, repo groups |
| codebase-memory-mcp | ~47k | MIT | 162 languages, cross-service HTTP edges, OOMs on big repos |
| serena | ~30k | — | LSP-backed symbol retrieval and editing |

Native agents still leave gaps: Cursor dropped its semantic index (v3.12),
Claude Code's LSP tool needs per-language manual setup, Codex has no LSP, and
Copilot measured semantic search at only 2% faster.

### The wedge (what nobody owns)

1. **Proven accuracy.** No tool publishes edge precision/recall against
   compiler or LSP ground truth, and users report graph tools doing worse than
   plain ripgrep.
2. **Hooks before and after edits.** Pull-only MCP tools fail because agents
   forget to call them. Hooks run every time.
3. **A cross-repo contract map with evidence and confidence**, under a
   permissive license, that does not crash on large repos.

Tessera competes on **trust**, not on language count or graph screenshots.

## 2. Users and jobs

**Primary user:** a developer using Claude Code (first), Cursor, Codex CLI,
Gemini CLI, or VS Code Copilot on a medium-to-large codebase, often a set of
services. Priority stacks: Node.js / TypeScript + React, and Java.

| # | Job | Today without Tessera |
| --- | --- | --- |
| J1 | Refactor (rename, change signature, remove a param, move a function) without missing call sites | Agent greps, misses dynamic or same-name callers, says "done" |
| J2 | Know the blast radius before an edit: callers, tests, routes, consumers | Agent reads files until context runs out, or skips it |
| J3 | Catch invented APIs before they land | Found at runtime or in review |
| J4 | Trace a request across services: page → route → handler → topic → consumer → table | Manual cross-repo grep |
| J5 | Spend fewer tokens on navigation | Secondary benefit; must be measured, not claimed |

Why not "just run `tsc` / `javac`": agents often don't; full type-checks take
10–60 s on large projects; JavaScript, Ruby, and Python have no compiler step;
and no compiler sees cross-repo or contract breaks. Tessera's check runs on
the changed slice in well under a second and covers all four cases. The docs
must say this plainly and recommend running the real type-checker too.

## 3. Goals, non-goals, anti-goals

### Goals

- **G1 — Two minutes to value.** From install to the first useful answer in
  under two minutes, with zero configuration: no mandatory `index` step, and
  the index is kept fresh automatically.
- **G2 — Published accuracy.** Reproducible precision/recall numbers for every
  deep-tier language, generated by a public benchmark.
- **G3 — Hooks catch real misses.** A public refactor eval shows how many call
  sites an agent misses with and without Tessera's hooks.
- **G4 — Scales.** Index a 100k-file monorepo without OOM; single-file
  re-index fast enough for a per-edit hook (see budgets in §9).
- **G5 — Easy to trust.** Apache-2.0, local-only, no telemetry by default,
  single binary, install works on macOS, Linux, and Windows.

### Non-goals

- LLM-extracted semantics, docs/PDF ingestion, embeddings or vector search.
- A hosted cloud service.
- Executing refactors (serena's job). Tessera reports; the agent edits.
- Competing on language count.

### Anti-goals (failure even if it technically works)

- **Noisy hooks.** If `verify` blocks agents on false positives, users
  uninstall. Only high-confidence findings may block; everything else is
  advisory.
- **Slow hooks.** A hook that adds noticeable latency to every edit gets
  disabled.
- **Claims nobody can reproduce**, including the current private-repo
  benchmarks in the README.
- **Growth hacks:** fake stars, star-begging, competitor bashing.
- **Broken install** on any of the three major OSes on launch day.
- Storing index data outside `.tessera/` or the user cache dir, or sending
  code anywhere. Agent config files are only written by `tessera init`, after
  showing the change and getting confirmation (§5.1).

## 4. Positioning

- **Headline:** "Your agent says done. Tessera checks."
- **Subhead:** Deterministic blast radius before every edit and verification
  after it — across files, repos, routes, topics, and tables. Local, Apache-2.0,
  one binary.
- **Three proof points, all reproducible:** accuracy table from `tessera-bench`;
  refactor-eval result (missed call sites with vs without hooks); a 30-second
  video of a hook blocking "done" and the agent fixing the missed callers.
- **Comparison table** against codegraph, codebase-memory-mcp, GitNexus,
  serena, graphify, and plain LSP, on: deterministic build, published accuracy,
  pre/post-edit hooks, cross-repo contracts with evidence, large-repo safety,
  license. Factual, sourced, no attacks.
- **Language support** is presented in tiers (decided by Saquib):
  - **Deep:** import- and scope-aware resolution, framework packs, contract
    facts. Starts with TS/JS/React and Java.
  - **Standard:** symbols, references, and imports at name level, labelled as
    such.
  - The README may lead with the total count but must show the tier table
    directly under it.

## 5. Product surface at v1.0

### 5.1 CLI (humans and hooks)

The 31 subcommands collapse to about 14. Breaking renames are allowed before
1.0 (no real user base yet).

| Command | Replaces | Purpose |
| --- | --- | --- |
| `init` | `init` | Detect installed agents; show a diff of every config change and ask y/N (`--yes` for scripts, `--dry-run` to only print); project-scoped files only, for detected agents; never edits `AGENTS.md` or Copilot instruction files without `--with-instructions`; user-global config only with `--global`; idempotent; `--agent <name>` |
| `status` | `doctor`, `stats` | Index health, freshness, repos, versions, fix commands |
| `find <name>` | `find-definition`, `signature`, `expand-symbol`, `get-outline` | Definition, signature, optional body, file outline |
| `search <pattern>` | `search` | Fuzzy and glob symbol search |
| `refs <symbol>` | `find-references`, `tests-for` | References with confidence; `--tests` filter |
| `blast [<symbol> \| --diff [rev]]` | `impact`, `diff-impact`, `siblings` | Ranked blast radius incl. tests to run and (M3) affected services; working-tree aware |
| `verify [--changed \| --diff rev \| --snippet -]` | `validate`, `validate-snippet` | Deterministic post-edit checks (§5.4); exit code for hooks/CI |
| `context <symbol>` | `context-pack`, `edit-prep` | One budgeted pre-edit bundle |
| `path <from> <to>` | `connect` | Call path; (M3) crosses services |
| `map <route\|topic\|table\|service> [q]` | — (M3) | Contract map queries |
| `export` | `export` | DOT / Mermaid / JSON |
| `ui` | — (M4) | Local web explorer |
| `index`, `watch` | same | Optional; indexing is automatic |
| `mcp [--http addr]` | `mcp`, `mcp-http` | MCP server |
| `hook <agent> <event>` | — | Internal entry point called by agent hooks |
| `completions` | same | Shell completions |

Removed: `plan-query`, `shell`, `snapshot`, `unused` (folded into
`search --unused`), `bench` (moves to `tessera-bench`, see §5.6).

### 5.2 MCP tools (agents)

At most nine tools: `find`, `search`, `refs`, `blast`, `verify`, `context`,
`path`, `map`, `status`. Requirements:

- Current MCP spec with version negotiation back to `2025-06-18`; correct
  JSON-RPC error codes; tool failures as `isError: true` results; no responses
  to notifications.
- `annotations.readOnlyHint: true` on every tool, `title`, `outputSchema`,
  `additionalProperties: false`.
- Compact text by default plus `structuredContent`; default cap around 2k
  tokens with cursor pagination and an explicit "truncated, call again with
  cursor X" hint.
- Every response carries a `repo` field once workspaces exist (M3).
- `_meta` token numbers are measured from the actual output, never constants.
- One registry defines each tool's name, schema, and handler, shared by CLI and
  MCP, so schemas cannot drift.
- HTTP transport: `Origin` validation, 202 for notification POSTs,
  `MCP-Protocol-Version` header handling, request timeouts.

### 5.3 Agent hooks — the wedge

Claude Code first, delivered as a **Claude Code plugin** in this repo
(`.claude-plugin/` plus a marketplace manifest) bundling the MCP server config,
hooks, the `/tessera` skill, and slash commands `/tessera:blast` and
`/tessera:verify`. Install from inside the agent:
`/plugin marketplace add iamsaquib8/tessera`.

| Event | Behaviour | Budget |
| --- | --- | --- |
| `SessionStart` | Ensure binary present and index fresh; record a baseline for this session | Must not block startup on a large repo; index in background if needed |
| `PreToolUse` (Edit / Write / MultiEdit) | If the edit touches a symbol with cross-file callers, inject a compact note: caller count, top call sites, tests to run | ≤150 tokens; once per symbol per session; silent when there are no callers |
| `PostToolUse` (Edit / Write / MultiEdit) | Re-index the edited file; run `verify` on changed symbols; block with exact `file:line` list only on high-confidence breakage | p95 budget in §9 |
| `Stop` | Run `verify` over everything changed since the session baseline; block "done" while high-confidence issues remain | Honour `stop_hook_active`; cap re-blocks to avoid loops |

#### Every agent, every model

Tessera is **model-agnostic**: it never calls an LLM, so it works the same
whether the agent runs Claude, GPT, Gemini, Grok, DeepSeek, Qwen, or a local
model. Support is defined per **agent**, not per model. Grok and DeepSeek users
get Tessera through whichever agent they run (for example OpenCode, Cline, Kilo
Code, Roo Code, Aider, Goose, or Claude Code pointed at DeepSeek's
Anthropic-compatible API), plus any first-party CLI those vendors ship.

Support comes in four layers, so every agent gets something:

| Layer | Works with | What it gives |
| --- | --- | --- |
| **Hook adapter** (tier A) | Agents whose hooks can block after an edit | Full edit-safety loop: pre-edit context, post-edit block, stop gate |
| **MCP** (tier B) | Any MCP client (stdio or HTTP) | All nine tools on demand |
| **Instructions** | Agents that read `AGENTS.md`, `GEMINI.md`, rules files, etc. | Tells the agent when to call `blast` / `verify`; only written with `--with-instructions` |
| **Git backstop** | Every agent, and humans | `tessera init --git-hook` installs a pre-commit `tessera verify --staged`; a broken edit cannot be committed regardless of which agent made it |

Each agent is an **adapter** in one registry: detection rule, MCP config path
and format (project and global), hook events and their input/output contract,
instructions file, and distribution channel (plugin, extension, directory).
Adding an agent means adding one adapter and one fixture test, which makes it
a good-first-issue for contributors.

Target agent list (to be confirmed against the support matrix below): Claude
Code, Cursor (IDE and CLI), Codex CLI, Gemini CLI, Google Antigravity, GitHub
Copilot (VS Code and CLI), Grok CLI, Qwen Code, OpenCode, Crush, Kilo Code, Roo
Code, Cline, Continue, Windsurf, Zed, Aider, Goose, Amp, Kiro, Factory Droid,
Warp, JetBrains Junie, Amazon Q Developer CLI.

Order of hook adapters: Claude Code first (launch), then the other tier-A
agents by user base. A sourced support matrix lives in `docs/agents.md` and is
the input for each adapter; anything the vendor docs don't confirm is marked
unverified and not implemented. `tessera init` writes whatever each detected
agent supports and prints what it could not do.

The builder must verify each agent's current hook contract (event names,
input/output JSON, block semantics, whether `PreToolUse` can add context)
against official docs before implementing; this design does not assume
undocumented behaviour.

### 5.4 `verify` — the check catalog

All checks are deterministic and carry a confidence. Only **high** blocks.

| ID | Check | Blocks when |
| --- | --- | --- |
| V1 | **Unresolved call** — new or changed code calls a symbol that does not exist (invented API) | Receiver or import resolves to a local module and the name is absent there |
| V2 | **Arity mismatch** — a signature changed and resolved call sites pass an incompatible argument count | Edge resolved with high confidence |
| V3 | **Dangling reference** — a removed or renamed symbol is still referenced | Edge resolved with high confidence |
| V4 | **Broken import** — imported name not exported by a local module, or local path no longer resolves | Always (local modules only) |
| V5 | **Contract change** (M3) — route method/path removed or changed with known consumers; topic renamed leaving orphan producers/consumers | Link confidence high |
| V6 | **Tests to run** — test files that reach changed symbols | Never (advisory) |

Calls into third-party packages are not flagged in v1 (cannot be verified
without type info). The same applies to methods inherited from third-party
classes and to generated members (e.g. Lombok). Standard-tier languages are
advisory-only: their findings never block. Exit codes: `0` clean, `1` blocking findings, `2` usage
error, `3` index error. Output formats: `agent` (terse, for hook reasons),
`human`, `json`, `sarif` (for CI).

### 5.5 Contract map (M3)

- **Facts layer**, separate from the symbol graph:
  - `nodes(kind, key, repo, file, line, attrs)` with kinds such as `route`,
    `http_call`, `topic`, `producer`, `consumer`, `table`, `model`,
    `migration`, `rpc`, `rpc_call`, `graphql_op`, `config_key`, `package`.
  - `links(kind, from, to, confidence, evidence)` where `evidence` records the
    rule id, `file:line`, and matched text.
- **Matching:** routes normalise to `METHOD /path/{}`; client URLs come from
  string literals and templates plus configured base URLs. Exact literal =
  high confidence, template with params = medium, concatenated variable = low.
- **Framework pack v1 (priority stack):** Express, NestJS, Next.js API routes,
  Fastify; `fetch` / axios / ky / React Query / SWR clients; Spring MVC
  annotations, Feign, WebClient / RestTemplate; Spring Kafka
  (`@KafkaListener`, `KafkaTemplate.send`) and kafkajs; OpenAPI 3; Flyway /
  Liquibase SQL, Sequelize / TypeORM / Prisma, JPA `@Entity` / `@Table`;
  `.proto` services and gRPC stubs. Rails routes and ActiveRecord follow as the
  first community-style pack.
- **Packs are declarative** (tree-sitter `.scm` queries plus small post-
  processors) with fixtures, so contributors can add frameworks without
  touching the core.
- **Workspaces:** `tessera.workspace.toml` lists repos; also auto-detect
  pnpm/yarn/npm workspaces, Gradle multi-project, and Maven modules. One DB per
  repo plus a derived workspace link DB (avoids SQLite writer contention).
- Prior art: Saquib's private `graphify.py` verbs (`topic`, `producers`,
  `consumers`, `route`, `openapi`, `migrations`, `tagged`, `depends-on`,
  `runtime`) documented in `~/.claude/skills/punk-records/_parts/graph-verbs.md`.
  The script itself is no longer on disk; port the behaviour, not the code.

### 5.6 `tessera-bench` — accuracy and refactor eval (M1, M2)

A public, reproducible benchmark, runnable in Docker, in its own repo
(`iamsaquib8/tessera-bench`) so it can stay neutral.

- **Corpus:** 6–10 public repos pinned to commits, covering TS, plain JS,
  React, Java, and one polyglot microservice app for contracts. Candidates:
  excalidraw, a plain-JS Node service (e.g. Ghost), NestJS sample apps,
  spring-petclinic and spring-petclinic-microservices, a JHipster React+Spring
  sample, GoogleCloudPlatform/microservices-demo.
- **Ground truth:** SCIP indexes from `scip-typescript` and `scip-java` at the
  pinned commits, mapped to function-level reference and call edges.
- **Accuracy metrics:**
  - Precision is reported per confidence tier (high / medium / low) over every
    edge Tessera emits for the sampled symbols.
  - Recall uses as denominator every SCIP call/reference edge whose target is
    defined in the repo, reported per category: direct call, method on a
    typed receiver, call inside a callback, JSX, interface/virtual dispatch,
    type reference.
  - Symbol sample: stratified random sample per repo (functions, methods,
    classes; split by fan-in bucket), with a fixed seed, at least 200 symbols
    per language.
  - Also report definition accuracy and the ambiguity rate (edges emitted as
    "ambiguous" rather than guessed).
- **Ops metrics:** cold index time, incremental re-index time, peak RAM, query
  p50/p95, output tokens.
- **Competitor adapters** for codegraph, codebase-memory-mcp, GitNexus,
  serena, and graphify at their latest releases and default configs, versions
  recorded, raw output published, and maintainers invited to fix their own
  adapter by PR.
- **Refactor eval (M2):** 30–50 refactor tasks on the corpus (rename, add a
  required param, remove a param, change a return shape, move a function). The
  oracle is the test suite / compile plus a ground-truth call-site check. Run a
  headless agent in three arms — baseline, MCP only, MCP plus hooks — three
  repeats each. Report missed call sites, task success, tokens, and wall time.
- **Eval account (decided by Saquib):** Saquib's Claude subscription through
  `claude -p`, using Claude Code's default model at eval time (the model
  users actually run), with the model id recorded in results. Run a 5-task
  pilot first to measure tokens and wall time per run, then size the full
  eval. The eval runner must tolerate rate limits (resume from checkpoint;
  a full run may take days).
- **Competitors (decided by Saquib):** published under Saquib's name, so the
  adapters must be fair: latest releases, default configs, versions and raw
  output recorded, maintainers invited to fix their adapter by PR. Tools whose
  default config needs a paid LLM key run in their code-only mode, and the
  results say so.

### 5.7 UI (M4)

`tessera ui` serves an embedded single-page app on `127.0.0.1`. Views:

1. **Change impact** (default): working-tree diff → changed symbols → callers →
   affected services, coloured by `verify` result.
2. **Contract map:** services as nodes, routes / topics / tables as edges.
3. **Symbol page:** references, path explorer, tests.
4. **Search.**

Large graphs are aggregated (service → directory → file); never render an
unreadable hairball. `tessera ui --export <dir>` writes a static site for a
hosted demo on GitHub Pages.

### 5.8 GitHub Action (M4)

`iamsaquib8/tessera-action`: on pull requests, index base and head (with
cache), run `blast --diff` and `verify --diff`, post one sticky comment, and
optionally fail on blocking findings. Listed on the Actions Marketplace as a
discovery channel.

### 5.9 Code-anchored notes (M5)

`tessera note add <symbol> "<text>"` stores a note with the symbol's content
hash. Notes appear in `context` and `blast`, and are flagged stale when the
hash changes. Small, cheap, and an unclaimed niche.

## 6. Engineering foundation (M0)

Concrete work from the architecture audit. The hands-on usability audit adds to
this list (§6.6).

### 6.1 Parsing

- Upgrade to tree-sitter **0.26.x** (MSRV-compatible; 0.27 needs Rust 1.90)
  and current grammar crates via `tree-sitter-language`.
- Parse `.ts` with the TypeScript grammar and `.tsx` with TSX (today `.ts` uses
  TSX and mis-parses `<T>x` casts).
- Split the extractor into `lang/<language>.rs` behind a trait; move node
  matching to `.scm` query files where practical.
- Check `has_error()` and report partially parsed files.
- Add a recursion-depth guard or iterative walk; fix the UTF-8 slice panic.
- Per-language golden fixtures (symbols, refs, imports, edges).

### 6.2 Storage

- Use the ids returned by `insert_symbols` instead of re-looking them up per
  reference; cached prepared statements.
- `PRAGMA user_version` with real migrations or rebuild-on-mismatch (the index
  is a cache, so rebuild is acceptable); stop writing in `open()`.
- `busy_timeout`; sorted walk (`sort_by_file_name`); honour `.gitignore` via
  the `ignore` crate; stop skipping Java package dirs named `build`, `out`,
  `target`, or `vendor` at any depth.
- Replace leading-wildcard `LIKE` joins with id joins.
- Remove the bloom filter and the bincode snapshot unless a benchmark proves
  they pay for themselves.

### 6.3 Freshness

- No mandatory `index` step: the first query indexes.
- Long-running processes (MCP server, `ui`, `watch`) use a filesystem watcher.
- CLI and hooks re-index only what changed (hooks receive the edited path).
- Freshness check budget in §9.

### 6.4 MCP

Rewrite per §5.2, with stdio and HTTP conformance tests (scripted transcripts;
use the official MCP inspector or conformance suite where available).

### 6.5 Clean-up and truth

- Delete `engine.rs`, the `cozo` feature, `--graph-engine`, `petgraph`,
  `plan_query`, hard-coded `_meta` numbers, and `edit_prep`'s duplicate
  `tests_for` call.
- Rewrite `ROADMAP.md` to match this design; fix README, `docs/architecture.md`
  (claims MCP reads the snapshot), and the `--help` text at `src/main.rs:839`
  (overstates `criticality`).
- Remove private-repo benchmark numbers from the README until `tessera-bench`
  replaces them.

### 6.6 Hands-on usability findings (2026-10-20)

Tessera v0.9.0 was run against four real repos with the DB kept outside each
repo. Build, clippy, fmt, and all 36 tests pass.

| Repo | Files | Refs | Index time | Peak RSS | DB size |
| --- | --- | --- | --- | --- | --- |
| tessera (Rust) | 36 | 4,151 | 0.12 s | 18 MB | 1 MB |
| testhub (JS) | 1,185 | 170,689 | 3.3 s (no-op re-run 0.09 s) | 31 MB | 27 MB |
| teststack (Ruby) | 1,306 | 283,751 | 38.2 s | 3.0 GB | 3.76 GB |
| frontend (JS/TS monorepo) | 45,349 | 2.48 M | **crashes** by default; `--full` 62.6 s | 166 MB | 407 MB |

What already works and should be kept: line-level reference precision for
direct calls (0 false lines; JS recall 145/145, 209/209), Ruby calls without
parentheses, the 0.09 s no-op incremental run, and `validate` near-miss
suggestions (`getPageInfoo` → `getPageInfo`, 0.98).

Blocking problems, all added to M0 unless noted:

1. **Crash above ~32k files.** `delete_files_not_in` builds one SQL
   placeholder per file (`src/db.rs:217-233`): `too many SQL variables`. Every
   incremental run, `watch`, and git hook fails on large monorepos. Delete in
   chunks or through a temp table.
2. **DB blow-up from minified files.** Each reference stores the full source
   line as context (`src/indexer.rs:848,910`); one minified vendor bundle
   produced ~2.7 GB. Honour `.gitignore`, skip minified and oversized files,
   cap stored context at ~200 chars, add `--exclude`.
3. **Callers resolved by name** (M1): built-ins such as `map.get`, `d.update`,
   and `File::open` attach to user functions; every `::new` shows 71 callers.
4. **Type and class usage invisible** (M1): `BaseWorker` (20 subclasses) has 0
   references; `unused --kind class` flags 153 of 155 testhub classes. Hold
   `unused` for classes back until type references exist.
5. **Silent fuzzy answers.** `find-definition` returns fuzzy matches as if
   they were definitions (`src/query.rs:96-98`). Mark them explicitly.
6. **Silent truncation.** `find_references` caps at 250, `impact` at 100,
   `imported-by` at 500, with no total or `truncated` flag. Add `total`,
   `truncated`, `limit`, and a cursor.
7. **Bloated MCP output.** Results are sent twice, pretty-printed
   (`src/mcp.rs:319-322`): `find_references` 86 KB, `impact` 131 KB.
8. **Non-deterministic output.** Five runs of `impact open` gave five
   different results (ties in hash-map order, `src/query.rs:174,402`). Sort
   every tie by a stable key.
9. **Test detection wrong.** `/test_` matches `test_cases_controller.rb`;
   top-level `tests/` and RSpec `_spec.rb` are missed; Jest `it(() => …)`
   callbacks have no caller (M1 for the callback part).
10. **Slow composite tools.** `edit-prep` 3.6–6 s, `context-pack` 1.8–2.6 s,
    `impact` 0.66–4.35 s, against a README claim of "sub-20 ms".
11. **Path defaults.** `--db` is relative to the current directory, not the
    repo. Discover the repo root (git root walk-up) and keep the DB under it.
    `doctor` should detect a stale `tessera` binary earlier on `PATH`
    (Saquib's machine has 0.4.0 in `~/.cargo/bin`).
12. **No reindex during MCP sessions**, and the server exits if the DB is
    missing. Covered by §6.3.
13. **Misleading helpers.** `edit-prep` suggests a command that fails;
    `validate-snippet` flags `JSON.parse`, `flatMap`, `Promise.allSettled`,
    and `_.chunk` (4 false alarms in 5); `imported-by util/util.js` says
    "nothing imports" for a file 342 files require. Import lookup must accept
    file paths, not only raw specifier strings.
14. **Built-in `bench` is wrong.** It walks `node_modules`, counts substring
    matches, and picked the probe `set` ("4919× cheaper"). Remove it; the
    replacement is `tessera-bench` (§5.6).
15. **No install path works.**

| Path | Status today |
| --- | --- |
| npm | Never published (404); postinstall would fetch a 404 asset and leave a broken launcher |
| Homebrew | Tap repo missing; formula points at a non-existent tag with placeholder sha256 |
| `curl \| sh` | `releases/latest` is v0.1.0 with 0 assets |
| Docker (GHCR) | Anonymous pull returns 401 (package private) |

M0 performance gate adds: peak RSS on teststack ≤ 500 MB and DB ≤ 300 MB
after the minified-file fix; frontend (45k files) indexes incrementally
without error; composite tools (`context`, `blast`) p95 ≤ 500 ms on testhub.

## 9. Constraints and budgets

- Rust, single static binary, Apache-2.0. Platforms: macOS arm64/x64, Linux
  x64/arm64 (glibc and musl), Windows x64.
- Local-only. The only network access is the explicit binary download during
  plugin bootstrap, verified by checksum.
- The index is a cache: schema changes may rebuild it; never migrate user data.
- **Performance budgets** (calibrate against the bench corpus in M0, then
  enforce in CI):
  - `PostToolUse` hook end-to-end p95 ≤ 300 ms for one changed file in a
    5k-file repo.
  - Freshness check ≤ 100 ms on a 10k-file repo.
  - 100k-file monorepo indexes without OOM, peak RSS ≤ 1.5 GB.
  - Query p95 ≤ 50 ms for `find` / `refs` on a 10k-file repo.
- Code style: match the repository; no multi-line block comments.

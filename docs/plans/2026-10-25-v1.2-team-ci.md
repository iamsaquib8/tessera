# v1.2 Team and CI: Implementation Plan

**Goal:** make Tessera part of every pull request, and cut CI minutes with
test selection a reviewer can trust.

**Spec:** ROADMAP.md "v1.2: Team and CI"; docs/design/2026-10-25-landscape.md
(test selection, review formats, baseline and accepted-break ideas, with
sources); docs/stability.md (everything here is additive).

## Global Constraints

- Additive under the 1.x contract: no flag, `--json` field, MCP argument or
  check id is removed or renamed; new ones are recorded in
  `tests/stability/*.json`.
- Tessera makes no network calls. Anything shared between machines is a
  file that CI or the user moves.
- Deterministic: the same index and change give byte-identical output.
- Hook latency budget unchanged; baseline and accepted-break checks are a
  hash lookup per finding.
- Every finding carries `fingerprint` (16 hex, line-independent); baseline,
  accepted breaks, SARIF `partialFingerprints` and GitLab `fingerprint` all
  use it.

## Review Focus

1. A selected-tests list never silently drops a test that a full-run
   trigger (lockfile, build file, config, fixture) should have forced.
2. A baseline or accepted-break file that is stale, malformed, or from
   another Tessera version degrades to "everything counts", never to
   "nothing blocks".
3. A cache file from a different version, config or repository is refused,
   not half-loaded.
4. Report formats escape paths and messages for their target (SARIF URIs,
   GitLab JSON, Azure logging commands, Bitbucket JSON).
5. `affected` on a repository with no tests, no git, or a detached HEAD
   prints a message and exits 0 or 2, never panics.

## Tasks

0. **Finding fingerprints** (done first: everything below keys on it).
1. **`tessera affected <rev>`.** Tests reached by the change through calls,
   imports and contracts, each with a reason (the changed symbol and the
   path from it); `--explain <test>` for why a test is or is not selected.
   Safety rails: new, changed and previously failing tests always run (a
   `--failed <file>` list); lockfile, build-file, config and fixture changes
   select the full suite with the reason; a `Tessera-No-Skip` commit
   trailer in the range selects everything. `--format jest | vitest |
   pytest | go-test | cargo | json | list`. Package boundaries from
   npm/pnpm/yarn workspaces, Cargo, Go and Maven modules; `--package` to
   restrict.
2. **Index cache files.** `tessera cache export <file>` and `tessera cache
   import <file>`: a compressed index snapshot with a header (Tessera
   version, schema, config fingerprint, tree hash). Import refuses a
   mismatched version or config; after import, freshness re-indexes only
   what differs from the working tree. The Action keys `actions/cache` on
   the merge base's tree and imports before indexing.
3. **Review formats.** `verify --format gitlab` (Code Quality JSON),
   `azure` (logging commands), `bitbucket` (Code Insights report and
   annotations JSON), `ndjson` (one finding per line, for agent loops).
   SARIF gains `partialFingerprints`. The Action uploads SARIF to code
   scanning when the token can (`upload-sarif: true`).
4. **Baseline.** `tessera baseline` writes `.tessera/baseline.json`
   (fingerprints of today's blocking findings, Tessera version);
   `verify`, hooks and CI treat a baselined finding as advisory.
   `verify --no-baseline` to see everything; `baseline --prune` drops
   entries that no longer fire.
5. **Accepted breaks.** `.tessera/accepted.toml` entries: `fingerprint`,
   `reason`, optional `expires` (date) and `by`. An accepted finding is
   advisory and says why; an expired entry is reported and no longer
   accepted. `tessera accept <fingerprint> --reason …` appends one.
6. **Action: merge gate and gaps.** The PR comment lists tests to run in a
   copyable block and "test gaps" (changed functions no test reaches);
   `fail-on: blocking | new` (new ignores baselined and accepted);
   `affected` output exposed as an Action output for the next CI step.
7. **Gate measurement.** On three public monorepos (pinned in
   tessera-bench), seed breaks and check that `affected` selects every test
   that fails and skips at least half of the suite on typical changes; a
   cached CI run indexes in under 10% of a cold run. Results in
   tessera-bench `results/`.
8. **Docs and release.** docs/ci.md (new: affected, cache, formats,
   baseline, accepted), README, CHANGELOG 1.2.0, version 1.2.0.

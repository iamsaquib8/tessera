# Tessera v1 Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Tessera from a name-matched single-repo code graph into the deterministic edit-safety layer described in the design, shipping M0 (foundation) first and continuing through M4 (v1.0) without stopping.

**Architecture:** M0 rebuilds the foundation in place: upgraded tree-sitter with per-language extractor modules, a gitignore-aware walker, schema v4 with rebuild-on-mismatch, automatic freshness, a consolidated query API behind eight tools, a spec-compliant MCP server, and a release pipeline whose every install path is smoke-tested. M1–M4 each get their own detailed plan, written at the start of that milestone against the code M0 produced (§ Milestone plans).

**Tech Stack:** Rust (stable, MSRV 1.82), tree-sitter 0.26.x + grammar crates on `tree-sitter-language`, rusqlite (bundled SQLite, WAL, FTS5), `ignore` (walk), `notify` (watch), `tiny_http` (MCP HTTP), clap + `clap_complete`, `insta` (snapshots), GitHub Actions, npm platform packages.

**Spec:** `docs/design/2026-10-21-overhaul.md` — read it before any task.

## Global Constraints

- Single static binary, Apache-2.0, MSRV `rust-version = "1.82"`; tree-sitter stays on 0.26.x (0.27 needs Rust 1.90).
- Platforms: macOS arm64/x64, Linux x64/arm64 (glibc and musl), Windows x64.
- Local-only: no network calls except the explicit binary download in install scripts and the plugin bootstrap; no telemetry.
- The index is a cache: a schema mismatch rebuilds it; never migrate in place.
- All paths stored and printed with forward slashes, relative to the repo root.
- Every list output is sorted by a stable key; identical input gives byte-identical output.
- Every list output reports `total`, `returned`, `truncated`, and `next_cursor`; nothing is silently capped.
- Fuzzy matches are always labelled as fuzzy.
- Token estimates are measured from the actual output (`ceil(chars / 4)`), never constants.
- Code style: match the repository; no multi-line block comments; at most one short line when the why is non-obvious.
- Breaking CLI/MCP/library renames are allowed before 1.0; `CHANGELOG.md` records old → new names.
- Stored reference context is capped at 200 characters, cut on a char boundary.
- Default `max_file_bytes` = 1 MiB; minified files are skipped (rule in Task 4).

## Review Focus

1. **Windows paths** — a repo on `C:\work\app` must store `src/a.ts`, never `src\a.ts`, in DB rows, CLI output, and MCP output. Test in Task 4.
2. **Invalid UTF-8 and BOM files** — Latin-1 or BOM-prefixed sources index lossily with a warning; the run never aborts. Test in Task 14.
3. **Symlinks** — symlinked directories are not followed and a symlink loop does not hang the walk. Test in Task 4.
4. **Concurrent access** — the MCP server re-indexing while a CLI query runs must not fail with `database is locked`. Test in Task 5.
5. **Empty or unsupported repo** — a directory with no supported files gives exit 0, an empty index, and an actionable message from `status` and `find`. Test in Task 10.

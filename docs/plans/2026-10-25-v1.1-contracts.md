# v1.1 Contract Map Completed: Implementation Plan

**Goal:** close what v0.13 left open: Express mount prefixes, GraphQL, config
keys, `path` across workspace repositories, Go/Python/Ruby web frameworks,
and HTTP/topic ground truth with a third untouched corpus.

**Spec:** ROADMAP.md "v1.1: The contract map, completed"; docs/contracts.md;
docs/stability.md (everything here is additive under the 1.x contract).

## Global Constraints

- Additive only: no `--json` field, MCP argument, or check id is removed or
  renamed (tests/stability.rs). New fact kinds and `map` kinds are additions.
- Every new rule has a fixture under `tests/fixtures/contracts-*` and an
  expectation in `tests/contracts.rs`; every V5-relevant change has a test in
  `tests/verify.rs`.
- Packs stay declarative (`packs/*.scm` + one `PACKS` entry with a regex
  gate); Rust only where a query cannot express the rule.
- No new blocking false positives: a contract whose provider may be outside
  what Tessera reads is advisory, never blocking.
- Hook latency budget unchanged (post-edit p95 300 ms on the perf fixture).

## Review Focus

1. A router mounted twice, or under a variable prefix, never produces a
   wrong high-confidence route.
2. GraphQL operation names collide across schemas; links are keyed by type
   and field, not operation name alone.
3. Config keys read through a wrapper (`config.get("X")`) and from `.env`
   files; secrets' values are never stored, only keys.
4. `path` across repositories terminates on cycles between repositories.
5. Python/Go/Ruby route decorators on undecorated functions are not routes.

## Tasks

1. **Express mount prefixes.** `app.use("/api", router)` where `router` is a
   local or imported Router: routes registered on it get the prefix.
   Mounted-twice routes appear under both prefixes; a variable prefix gives
   medium confidence. V5's mounted-router advisory stays for prefixes it
   cannot resolve.
2. **GraphQL.** `.graphql`/`.gql` schemas and `gql`/`graphql` tagged
   templates: `type Query { user }` declares `graphql query user`; resolvers
   (Apollo resolver maps, NestJS `@Query`/`@Mutation`/`@Resolver`) provide;
   client operations (`gql` documents, `useQuery`) consume, keyed by root
   field. `map graphql`.
3. **Config keys.** `process.env.X`, `import.meta.env.X`, `os.Getenv`,
   `os.environ[...]`/`getenv`, `System.getenv`, `@Value("${x}")`, Spring
   `application.yml/properties` keys, `.env*` files and Docker/compose
   `environment:` blocks: setters vs readers, keyed `config <name>`. Values
   are never stored. `map config`.
4. **`path` across repositories.** In a workspace, contracts link symbols in
   different repositories' indexes; `path` searches across them with a
   visited set per (repo, symbol).
5. **Go, Python, Ruby frameworks.** Packs for Go `net/http`
   (`HandleFunc`), chi, gin, echo; Python FastAPI, Flask, Django `path()`;
   Ruby Rails `routes.rb`; clients: Go `http.Get/NewRequest`, Python
   `requests`/`httpx`, Ruby `Net::HTTP`/`Faraday`.
6. **Ground truth.** tessera-bench gets hand-labelled HTTP routes and topics
   for two corpora and a third contract corpus nobody tuned against; results
   published in `results/README.md`, docs/contracts.md updated.
7. **Docs and release.** docs/contracts.md "What it reads" and "Limits",
   CHANGELOG 1.1.0, version 1.1.0.

# M4 v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Tessera 1.0: a local UI that shows a change's impact and the contract map, a GitHub Action that comments on pull requests, frozen CLI/MCP/JSON contracts, and the launch assets (docs, translated READMEs, pitch kit).

**Architecture:** `tessera ui` serves one embedded page (HTML, CSS and vanilla JS compiled into the binary, no build step, no CDN) and a small JSON API over the same queries the CLI uses; `--export` writes the page with pre-computed JSON so it runs from GitHub Pages. The pull-request report is a Rust renderer (`verify --format markdown`), so the Action is a thin composite wrapper. The contract freeze is a test that pins every `--json` shape and MCP tool schema.

**Spec:** `docs/design/2026-10-21-overhaul.md` §5.7, §5.8, §7, §8 (M4 row).

## Global Constraints

Everything in the M0–M3 plans still applies. In addition:

- **Local only:** the UI binds `127.0.0.1` (a port flag, never `0.0.0.0` by default), loads nothing from the network, and has no telemetry.
- **Readable at any size:** graphs aggregate (service → directory → file) above 60 nodes; the change-impact view lists, it does not draw a hairball.
- **Gate:** the UI works on microservices-demo and on a 45k-file repository; the Action runs on this repository's own pull requests; `--json` shapes and MCP schemas are pinned by tests; launch assets exist (publishing them is Saquib's call).

## Review Focus

1. **A dirty or detached working tree** in the change-impact view (no `HEAD`, or a rebase in progress) shows a message, not a crash.
2. **Huge diffs** (thousands of files) are summarised, top symbols first.
3. **HTML injection:** symbol names, paths and evidence are escaped everywhere in the page.
4. **Export portability:** the exported site works from a subpath (`/tessera/demo/`) with relative URLs only.
5. **Action on forks:** comment posting degrades to a job summary when the token cannot write.

## Tasks

### Task 1: PR report

`verify --format markdown`: blocking problems, advisory findings, contract changes (V5 and the services the changed files serve), callers of changed symbols ranked (top 10), tests to run, in a collapsed-details layout under 65,000 characters. **Tests:** a fixture diff renders the expected sections; escaping of `|` and backticks.

### Task 2: `tessera ui`

`src/ui/{mod.rs,page.html}`: `tessera ui [--port N] [--open] [--export DIR]`. API: `/api/status`, `/api/impact?diff=REV`, `/api/map?kind=&q=`, `/api/services`, `/api/symbol?name=`, `/api/search?q=`, `/api/path?from=&to=`. Views: change impact (default), contract map (services as nodes, contracts as edges, aggregated), symbol page, search. **Tests:** API responses for the TypeScript fixture; the page has no external URLs; `--export` writes `index.html` and `data/*.json` with relative links.

### Task 3: GitHub Action

`action/action.yml` (composite): install the release binary for the runner, index base and head with an actions cache keyed by the base sha, run `verify --diff base --format markdown`, post or update one sticky comment (`<!-- tessera -->` marker), fall back to the job summary, optional `fail-on: blocking`. `.github/workflows/tessera.yml` runs it on this repository. **Tests:** `tests/action.rs` checks the manifest's inputs and that every command it runs exists in the CLI.

### Task 4: Contract freeze

`docs/stability.md` (what 1.x keeps stable: commands and flags, exit codes, `--json` fields, MCP tool names and schemas, the hook payload contract) and `tests/stability.rs` pinning them against `tests/stability/*.json`.

### Task 5: Launch assets and 1.0

README "works with" grid (agents by tier), translated READMEs (zh-CN, ja, ko, es, pt-BR) marked as drafts for review, `launch/pitch/` (60-second demo script, 5-slide deck, one-pager), CHANGELOG 1.0.0, version 1.0.0.
